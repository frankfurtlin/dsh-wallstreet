## 2. 值得抄的（按性价比排序，附对方位置）

### ① AI 摘要的 maxTokens 实测曲线 —— 我们踩在坑里

对方 README 记了真机数据（`packages/rss/README.md` AI 摘要一节）：

| maxTokens | 20 条里成功 |
|---|---|
| 200 | 7 条 |
| 1024 | 12 条 |
| **4096** | **20 条全成功**（整轮 48s，单条 ~7s） |

原因是推理 token 与正文**共享**这个预算：太小的话模型还没写出正文就把预算耗在推理上，
finish 变成 `max-tokens`，这条摘要就废了。

我们 `lib/hub/summarize.js` 现在写死 **700**。今天 7 条成功、几条失败（日志里是 TRANSPORT，
但也可能混着被截断的）。**这是立刻该改的一条**。

### ② 失败原因要聚合成分布，而不是只写日志

对方 `aiSummary.failures` 给「最多 3 类原因 + 次数」，Markdown 里也写
（例：`原因：终止原因 max-tokens（…）×8`）。他们明确写了为什么要这么做：
「早先只有一句『N 条失败』，既分不清超时/限流/provider 报错，也无从判断是不是插件的问题」。

我们现在失败只进 journal，面板和 API 都看不到。`/hub/stats` 应该带 `summary.failures`。

### ③ 摘要输出要「清洗」，不要只认 JSON

对方把 LLM 调用拆成纯函数并用 40+ 条单测覆盖（`test/ai-summary.test.ts`）：
`buildAiSummaryMessages` / `cleanAiSummary` / `aiCacheKey` / `resolveAiRoute` / `callAiSummary`。
其中 `cleanAiSummary` 干的是：去整体引号书名号、去 markdown 加粗/标题/列表前缀、压换行、
纯空白视为失败。

我们是「严格 JSON，解析不出来就整条丢」。更稳的做法是**两级**：先按 JSON 解，
失败再退回「纯文本清洗」兜底——至少能留一句话。

### ④ 上游调用应该有一个统一模块，错误要分类

`dsh-openfin/lib/upstream.js` 的规则写得很清楚：

- UA 必须自报插件名（「有些东财边缘节点对 Node 默认 UA 直接 403」）；
- 每请求超时 4s，**总预算 5.5s 且重试必须在预算内**（不然 4s 超时 + 重试永远赶不上 6s 的整轮预算）；
- 只对可重试错误重试一次（timeout/network），4xx 不重试；
- 错误统一抛 `UpstreamError`，带稳定 `code`（`timeout|network|http|parse|aborted`），
  上层据此在 `parts[].error` 写一句人话。

我们 `lib/hub/sources.js` 是 12 个适配器各写各的 fetch，错误只有字符串。分类错误能直接改善
面板「最近失败」那一列的可读性。

### ⑤ 缓存要有「过期也能读」的一档

`dsh-openfin/lib/cache.js` 三件套：`memo(key, ttl, loader)`（顺带并发去重，防一页打 N 次上游）、
`peek(key)`（**过期也读得到**，上游挂时用它兜底）、`set(key, …)`（预热/测试），
外加 `maxEntries` 上限与 sweep。

我们现在只有 TTL 缓存：过期就是空。面板在上游抽风时会直接少一块。stale-while-revalidate
是低成本的体感提升。

### ⑥ 板块列表按**市值**排序一次拿全（我们按涨跌幅翻 5 页）

`dsh-openfin/lib/boards.js` 的注释写了理由和参数：

```
Board list:  fs=m:90+t:2  fid=f20（市值）pz=150  →  热力图从重板块开始，且一页覆盖全部行业板块
Constituents: fs=b:<BK>   fid=f6（成交额）pz=10  →  板块抽屉只展示成交额前 10
Board meta:   stock/get?secid=90.<BK>&fields=f43,f57,f58,f170
SECTOR_TTL_MS = 30s；成分股 + 板块元信息两个请求共 5s 预算
```

我们现在按 `fid=f3`（涨跌幅）排、翻 5 页（`BOARD_MAX_PAGES=5`）——**这正是今天被 RST 打断、
只拿到 100 个板块的原因**。按市值排一页 150 条就能覆盖，请求数从 5 降到 1。

（这条**本次未能实测**：东财 push2 现在对本机全 RST。对方注释里有实测记录，值得照改。）

### ⑦ 我们漏掉的一个源：东财财经快讯（缺了 `req_trace`）

`dsh-openfin/lib/news.js`：

```
https://np-listapi.eastmoney.com/comm/web/getNewsByColumns
  ?client=web&biz=web_news_col&column=344&order=1&needInteractData=0&page_index=1&page_size=8&req_trace=1
```

注释点名：**「该端点要求 `req_trace=1`，没有它会返回错误信封」**。我们前几天探测东财快讯时
拿到的就是 87 字节的 `{"code":0,"message":"Required String parameter 'req_trace' is not present"}`，
当时判断「空响应」放弃了。

**本轮实测**（2026-11-25 16:52，push2 正在 RST 的同时）：

```
带 req_trace=1 → 200, 6647 B, {"code":"1","data":{"list":[…]}} 正常给稿
不带          → 200,   87 B, {"code":0,"message":"Required String parameter 'req_trace' is not present"}
```

顺带一个结论：**东财不同子服务是独立限流的**——`push2`（行情）全 RST 的时候，
`np-listapi`（资讯）、`reportapi`（研报）、`np-anotice-stock`（公告）都正常。这解释了为什么
我们的公告/研报源一直好使、行情源间歇抽风。

### ⑧ 订阅源/数据源应该可在面板维护

RSS 插件把「内置渠道 + 自定义源 + 订阅源目录」做成了设置面：OPML 导入导出、
目录多来源（内置快照 + 任意 OPML，TTL 12h 静默刷新，**单个目录源失败不影响整个目录**，
响应体 8MB 上限，inflight 去重）。`dsh-finance-plugins` 的 `dsh-tool-datasource-config` 更直接：
`ctx.inject(['settings'])` + `settings.register('finance-datasource', z.object({...}), {base})`
+ `token` 字段 `.role('secret')`，再用两个 tool（`configure_datasource` / `get_datasource_config`）
让模型也能配。

我们是 12 个源写死在 `sources.js` 里，用户不能关、不能调频。这是「容器型」产品缺的一块。

### ⑨ systemPrompt 注入 vs tool：两条路都成立

RSS 插件的选择是**把当天 digest 前 8 条注入 systemPrompt**（按条数收口，其余指到当天文件），
理由是「模型问『今天值得读什么』时可以直接引用」，并且开关热生效。

我们选的是 **`wallstreet_news` tool**（按需查、不占每轮上下文）。两者不冲突：
把「今天最重要的 3 条」做成可选的 systemPrompt 片段，是低成本的高价值补充。

### ⑩ 测试要能拆开测

对方 `test/ai-summary.test.ts` 28 KB，覆盖消息构造、输出清洗、缓存 key/TTL/LRU、模型路由
优先级、store 白名单校验、渲染、LLM 终止分支、端到端降级路径；IO 全隔离到临时目录、
网络用 stub fetch。

我们的 `verification/verify-hub.mjs` 只能整体假一个 ctx 测「能跑通」，测不了「消息长什么样」
「输出怎么清洗」「路由优先级」。值得按同样的切法拆一次。

## 5. 第二轮：看的是「实现细节」而不是「功能清单」

上一轮看功能与接口，这一轮挑了几个之前没展开的模块读实现。

### 5.1 near-duplicate 要按脚本分词（`JohnXu22786/rss-digest` `src/dedupe.ts`）

他们的去重分两层：精确 = 归一化后的 sha1；模糊 = **token-set Jaccard**，而且是
**按脚本切词**——拉丁文用词边界，CJK 用字符 bigram。归一化先过 NFKC、去控制字符、
大小写折叠；CJK 直接把分隔符去掉（`你好，世界` == `你好 世界`）。整个模块无 IO、纯函数。

我们现在的 `titleSimilarity` = char trigram Jaccard ∪ LCS 占比，**中英混排会失真**：
英文标题用 trigram 尚可，但「NVIDIA beats earnings」与「英伟达业绩超预期」之间没有任何
字面重合，两条永远聚不到一起。按脚本选 token 至少能让英文源之间（sina-global 有英文稿）
互相合并得更准，也让 CJK 的 bigram 比 trigram 更敏感（短标题改进明显）。

### 5.2 模型路由要有兜底（`rss-digest` `src/dsh-llm.ts`）

他们解析 provider/model 的顺序是：显式配置 → `llm.listProviders()` 挑一个（优先
`deepseek|official`）→ `llm.listModels(provider)` 挑一个（优先 `chat|flash|deepseek|v3|r1|pro`）。
而且**延迟到第一次调用才解析**，理由写明是「HMR 或晚注册的适配器要被尊重」。

我们只读 `agentDefaultModel.currentSelection()`，拿不到就整段降级（今天日志里真出现过
「宿主没有可用的默认模型」）。加两层兜底能显著提高摘要覆盖率。

### 5.3 快照的四态契约（`dsh-openfin/lib/snapshot.js`）

一个聚合快照拆成若干 part，每个 part 只有四种归宿：

| 情况 | 返回 |
|---|---|
| 缓存新鲜 | 直接给，`ok:true` |
| loader 成功 | 给并写缓存，`ok:true` |
| loader 失败但有过期缓存 | **给旧值**，顶层 `stale:true`，`ok:true` |
| 连缓存都没有 | 空默认值 + `parts[].ok:false` + 短错误码 |

外加：每个 part 独立 deadline（默认 6s），**超时的那个 promise 不取消**，继续跑完写进缓存，
下一轮直接用。注释里那句话值得抄：「一个病态的上游不该把整页拖住」。

我们的 `/overview` 现在是「分区 warning 字符串」，面板只能显示一句「XX 暂不可用」，
没有 `stale` 标记、没有耗时、超时也不会把结果留给下一轮。

### 5.4 外部内容进模型上下文必须截断（`rss` `src/index.ts`）

他们给 systemPrompt 注入段落的每个字段都设了上限：标题 200、链接 500、来源 60、AI 摘要 100；
还专门写了理由——「外部 feed 把一个 `<title>` 写成 1 MB 就能把 systemPrompt 撑爆，
**而宿主侧没有任何一层会截它**」。另外 `safeLink()` 只放行 http(s)，防止
`javascript:` / `data:` 混进注入文本。

我们的 `wallstreet_news` 工具同样把外部标题和 URL 拼给模型：标题截了 120，**URL 没截、
总输出没上限**（limit 50 时可能几十 KB）。这是纯防御性缺口。

### 5.5 「今日头版」是一种独立的呈现形态（`damlys99/dsh-morning-paper`）

它把「你离开这段时间发生了什么」排成一张**报纸**：masthead、dateline、boxed bulletin
（等你处理的事）、带首字下沉的导语、分栏、小字注脚；数据**全部由事件日志算出，never
written by a model**。头版第一行就是五个数：`away 42m | 751 events | 28m wall clock |
turn 18 | 0 actions required`。

对我们的意义不是排版，而是**「先给结论、再给列表」的入口**：资讯中心现在是一张按时间排的
长列表，用户要自己从 1500 条里找重要的事。一个「今日头版」可以是一屏：
今日要闻 top5 + 板块异动前 3 + 我关注的票有没有公告 + 数量统计——全部规则可算，不烧 token。

### 5.6 每天落一份 Markdown digest（`rss-digest` / `rss`）

两家都会把当天结果写成 Markdown 文件（rss 落 `~/.dsh/rss-digest/YYYY-MM-DD.md` + `latest.json`）。
好处是不占上下文也能被外部消费（知识库收录、cron 邮件、别的 agent 直接读）。

我们只有 SQLite + 面板。但本机已有现成的落库管线（`scripts/kb/kb_publish.py`），
每天导出一份 `data/digest/YYYY-MM-DD.md` 并投喂知识库，成本很低。

### 5.7 其他看过但优先级低的

- **关键词高亮 / 产业链提及**（`marketingdashboard`）：快讯里自动高亮宏观词与产业链标的。
  我们有 ticker/sector chips 但没有高亮；属于锦上添花。
- **产业链全景 / 美债 2s10s / 财报日历**（同 repo）：是**内容维度**的扩展，不是当前这版要解决的问题。
- **配置驱动的仪表盘布局**（同 repo `src/config/dashboard.ts`）：把「显示什么卡片」做成配置数组。
  我们的视图是写死的；如果以后要「自定义首页」可以借。
- **`dsh_kline` 的 150KB 工具目录 JSON**：把所有能力编成一张 catalog 再统一注册，适合工具很多的插件；
  我们只有 1 个工具，用不上。
